# bip39-explorer

A GUI for exploring the [BIP-39 English wordlist](https://github.com/bitcoin/bips/blob/master/bip-0039/english.txt)
— 2048 words — with a search box that finds words by more than substring.

> **Status: design.** Nothing is built yet. The concept pitch below is the
> current deliverable; the stack and packaging are still open questions.

## The pitch

**[`docs/design/concepts.html`](./docs/design/concepts.html)** — four design
concepts with live renderings. One query bar drives all four, and the search
engine in the page is the real one, running over all 2048 words.

| | Concept | What it is |
|---|---|---|
| 01 | **Roster** | CountRoster's card grid, with words where trackers were. Browsing and learning. |
| 02 | **Console** | One ranked list grouped by *why* each word matched, with a detail pane. Recovery. |
| 03 | **Field** | All 2048 words as one cell each, lighting and dimming live as you type. Scale and teaching. |
| 04 | **Orbit** | The word detail page: the word at the centre, its neighbours on five spokes. |

They aren't four apps — they're four views of one engine. The recommendation
is to ship Roster as the shell, Console behind a density toggle, Field as a
collapsible strip, and Orbit as the word page the other three link into.

## Search: a ladder of match reasons

Every result says which rung it came in on. All but the last are derived from
the wordlist itself, and the whole pass over 2048 words is fast enough to run
on every keystroke with no debounce and no index.

| Rung | Catches | Example |
|---|---|---|
| exact | The word itself | `bird` |
| starts with | Normal typing — and at four characters, exactly one word (BIP-39 guarantees unique 4-letter prefixes) | `sil` → `silent` |
| contains | Half-remembered middles and endings | `-tion` |
| 1–2 edits | Transcription slips, via Damerau–Levenshtein | `recieve` → `receive` |
| sounds like | Dictation and accents, via a phonetic key | `krane` → `crane` |
| letters in order | Skipped letters and shorthand | `dscvr` → `discover` |
| related meaning | The real ask | `bird` → `eagle`, `nest`, `wing` |

Meaning needs a **confident anchor** — a strong letter-match that also starts
like the query or sounds like it — so `ocen` reaches the sea via `ocean`, while
the fragment `tion` doesn't drag in `lion`'s animals.

The pitch page runs a hand-built topic index (40 topics, 677 of the 2048 words)
purely to make the interaction judgeable. The proposal for v1 is to generate
the index offline from WordNet plus embedding neighbours and commit the result
as static JSON — no runtime model, no API, fully offline.

## Adopted from [CountRoster](https://github.com/chinmay28/countroster)

- **Design tokens** — the same custom-property block: teal `#4ecdc4` on
  `#fafafa`, 12 px radius, two-step shadow, `prefers-color-scheme` dark, BEM-ish
  class names, system UI type. Added for this subject: monospace for every word
  and number, and five relation hues that carry information rather than decorate.
- **Versioning** — `vMAJOR.MINOR.<git commit count>`, assembled by one script,
  inlined at build time, shown under the wordmark in tabular monospace. A build
  without git reports patch `0`; a shallow clone is refused rather than allowed
  to report a plausible lie.
- **QuickStart** — `curl … | sudo bash`: root check, dedicated system user,
  hardened systemd unit, health poll with rollback, re-runnable to upgrade.
  Simpler here in one way — no database, so the snapshot/restore half of the
  script drops out.

## Safety

This is a static, offline word reference. There is deliberately nowhere in the
UI to enter twelve words in a row: no phrase field, no network calls, no
storage. **Never type a real seed phrase into anything.**

## Data

[`data/english.txt`](./data/english.txt) — the 2048-word list, sha256
`2f5eed53a4727b4bf8880d8f3f199efc90e58503646d9ff8eff3a2ed3b24dbda`, matching
the hash published in the BIP-39 text.

## Open questions

1. **Packaging** — CountRoster's Go binary and systemd unit, or a plain static
   bundle? *Default: both — a static bundle plus a small Go binary that embeds
   it, so the QuickStart story survives.*
2. **Stack** — mirror CountRoster's Vite + React + TypeScript, or stay
   dependency-free? *Default: Vite + React + TypeScript, with Vitest for the engine.*
3. **Semantic index** — WordNet, embeddings, or a hand-edited topic list?
   *Default: WordNet plus embeddings, generated by a committed script.*
4. **Scope of the bits view** — index and binary only, or a full checksum
   explainer? *Default: index, hex and 11 bits per word; no phrase-level tooling.*
